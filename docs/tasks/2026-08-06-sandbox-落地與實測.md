## 目標

把 `claude-code-sandbox` 的開發規範落地到這個專案,並**拿這個專案當規範的第一個真實案例**

(D1-1 觸發訊號數值、D1-2 archive 組織方式、D7 漏連結啟發式)——

## 已量到的事實(不是推論,附證據)

1. **`src/graphrag/` 用的不是 Anthropic 的 LLM provider**,且整個 repo 沒有
   anthropic/claude 相依。
   證據:`grep -rEl 'openai|langchain_openai|google.generativeai|genai|mistralai|cohere|ollama'`
   命中 `src/graphrag/config.py`、`src/graphrag/extractor.py`、`pyproject.toml`、
   `tests/unit/test_ingestion.py`;`grep -rEil 'anthropic|claude' src pyproject.toml` 回空。
   → 改那塊時不要套用 Claude API 的指引

2. **從 repo 量不出目前講哪個版本的 MCP spec。**
   `pyproject.toml:14` 是 `mcp>=1.13.1` —— 浮動下限、沒有 lockfile,
   所以實際版本取決於安裝環境而非 commit。
   → **升級任務的第一步是量測已安裝的套件版本,不是讀 `pyproject.toml` 推論**(鐵則 3)

3. **範圍外的疑點,未確認**:`pyproject.toml` 宣告 `requires-python = ">=3.8"`、
   `target-version = py38`,但 `mcp` SDK 據稱要求 3.10+。若成立,宣告的下限已經過期,
   而且**可能直接擋住 spec 升級**。照規範不擅自修,但升級前必須量測確認

4. **第 2 條的量測結果**:scratchpad 全新 venv 執行 `pip install -e ".[dev]"`(依 `pyproject.toml`
   浮動下限 `mcp>=1.13.1`),實際解析安裝到 **`mcp` 2.0.0**;其 `mcp-types` 子套件的
   `MODERN_PROTOCOL_VERSIONS = ('2026-07-28',)`,即目前實際講的 **MCP protocol 版本是 `2026-07-28`**。
   證據:`pip show mcp` → `Version: 2.0.0`;
   `python -c "from mcp_types.version import MODERN_PROTOCOL_VERSIONS; print(MODERN_PROTOCOL_VERSIONS)"`
   → `('2026-07-28',)`

5. **第 3 條的疑點證實成立**:`importlib.metadata.metadata('mcp').get('Requires-Python')`
   → `>=3.10`,而 `pyproject.toml:12` 宣告 `requires-python = ">=3.8"`。宣告下限確實已過期。
   風險不是「直接擋住升級」,而是隱性的:在 Python 3.8/3.9 環境下 `pip install` 不會報錯,
   pip 解析器會靜默回退安裝遠舊於 2.0.0 的 `mcp` 版本,沒有任何警告。
   → 這是下一步第 5 項(判斷 spec 升級強度)的關鍵輸入:`requires-python` 下限必須同步上修
   到 `>=3.10`,否則新舊 `mcp` 版本可能被靜默混用

# 掛入 claude-sandbox 開發規範並實測

狀態：進行中
強度：L2
日期：2026-08-06

## 目標

把 `claude-code-sandbox` 的開發規範落地到這個專案,並**拿這個專案當規範的第一個真實案例**
——目的不只是讓 mcp-fda 有規範可用,更是要讓規範自己被真實工作驗證,把踩到的問題
回饋回 sandbox。

規範目前的狀態是「全部都還是意圖,沒有任何一條被跑起來的系統驗證過」。
sandbox 的 `docs/DECISIONS.md` 有三個待決事項明文卡在「等真實使用經驗」
(D1-1 觸發訊號數值、D1-2 archive 組織方式、D7 漏連結啟發式)——
只有實際使用能解開它們。

## 範圍

**包含**：
- 落地:根 `CLAUDE.md` 引用、`docs/` 三個檔案、submodule 釘版
- 驗證引用真的生效(這件事在 sandbox 自己身上永遠測不到)
- 量測 MCP 現況(見下方「已量到的事實」第 2 條)
- D7 的結構檢查腳本(第一版,只做結構層)

**不包含**：
- **MCP spec 升級本身** —— 要先量到現況、判強度、講計畫才能動。
  這是下一個任務,不是這一個
- 改 `claude-sandbox/` 裡的任何檔案(禁令 5:不改上游/第三方套件)。
  規範要改就在 sandbox repo 改,再 `submodule update`
- mcp-fda 的功能變更

4. 至少產出一則真實的 `K-n` 條目,以及一則對 sandbox 的回饋(哪條規則不好用/缺什麼)

## 假設(若不對請說)

1. **這個專案是規範的測試載體,不是規範的目的地。** 遇到規範本身的問題,
   記錄下來回饋 sandbox,不要在這裡就地改規範
2. **submodule 釘在 `3846eac`(sandbox `main`)。** 規範更新要明確執行
   `git submodule update --remote claude-sandbox` 才會跟進,不會自動漂移
3. 根 `CLAUDE.md` 刻意只放一行引用,**不放專案資訊**(路徑表/指令/注意事項)——
   使用者明確選了最小版。之後要加是另一個決定

## 已量到的事實(不是推論,附證據)

1. **`src/graphrag/` 用的不是 Anthropic 的 LLM provider**,且整個 repo 沒有
   anthropic/claude 相依。
   證據:`grep -rEl 'openai|langchain_openai|google.generativeai|genai|mistralai|cohere|ollama'`
   命中 `src/graphrag/config.py`、`src/graphrag/extractor.py`、`pyproject.toml`、
   `tests/unit/test_ingestion.py`;`grep -rEil 'anthropic|claude' src pyproject.toml` 回空。
   → 改那塊時不要套用 Claude API 的指引

2. **從 repo 量不出目前講哪個版本的 MCP spec。**
   `pyproject.toml:14` 是 `mcp>=1.13.1` —— 浮動下限、沒有 lockfile,
   所以實際版本取決於安裝環境而非 commit。
   → **升級任務的第一步是量測已安裝的套件版本,不是讀 `pyproject.toml` 推論**(鐵則 3)

3. **範圍外的疑點,未確認**:`pyproject.toml` 宣告 `requires-python = ">=3.8"`、
   `target-version = py38`,但 `mcp` SDK 據稱要求 3.10+。若成立,宣告的下限已經過期,
   而且**可能直接擋住 spec 升級**。照規範不擅自修,但升級前必須量測確認
